# cue M2: core domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `crates/cue-core` (lib `cue_core`), a pure, fully tested Rust crate that holds every rule in spec §5 that is logic rather than I/O.

**Architecture:** The engine (M3) owns one `State` (persisted) and one `Runtime` (in memory). On every coalesced event it hands core a `Snapshot` of CoreAudio, and `reconcile()` mutates `State` and returns the `Action`s to execute plus one `Reason` per role. UI commands are pure transitions on the same `State`. `panel_state()` renders the view model. All UID rewriting goes through one registry module (`identity/registry.rs`), which alias merge and forget both use.

**Tech Stack:** Rust (workspace edition from M1), `serde` (derive), `serde_json`. Nothing else.

**Spec:** `docs/superpowers/specs/2026-11-23-cue-design.md` (§5, §6, §9). Also read `docs/adr/0003-strict-priority-policy.md`, `docs/adr/0004-logging-and-debug-mode.md`, and `docs/audit/core-audio-and-switching.md` §3.3, §5, §6, §7.

**Branch:** `m2-core`, off `main` after M1 merged. Assumes M1 created `crates/cue-core` as an empty lib in the workspace and `clippy.toml` with `too-many-lines-threshold = 40`.

## Global Constraints

- `crates/cue-core/src/lib.rs` starts with `#![forbid(unsafe_code)]`.
- Dependencies: `serde = { version = "1", features = ["derive"] }`, `serde_json = "1"`. No `thiserror` (two small error enums get a hand-written `Display`), no `log`, no tauri, no objc2.
- No I/O, no clock, no logging in core. Time is injected as `Timestamp` (ms since the Unix epoch).
- Every non-test file is 300 lines or fewer, as measured by `pnpm check:size` (M1: lines from the first bare `#[cfg(test)]` line are not counted). Every function is 40 lines or fewer.
- Nothing is keyed or persisted by `AudioObjectID`. The only key is `DeviceKey` (the CoreAudio device UID).
- State file: `schema_version: 1`, snake_case keys, unknown top-level keys preserved.
- Loop guard: 3 corrective writes per role in a sliding 10 s window (`10_000` ms).
- Notification and panel copy: `cue paused auto-switch: <device> kept taking <role>`, where `<role>` is `output` or `input`.
- Unit tests for private logic go inline (`#[cfg(test)] mod tests`). Behaviour tests go in `crates/cue-core/tests/*.rs` against the public API, sharing `tests/common/mod.rs`.
- Quality gate for this crate: `cargo test -p cue-core`, `cargo clippy -p cue-core --all-targets -- -D warnings`, `cargo fmt --all --check`.

## Review Focus

1. **The current default is not a ranked device, or there is none** (hidden device, not-alive device, `current = None`). Expected: no panic, `Reason.current` reports it, a desired device is still set, and the panel shows the current hidden device as an unranked row. Pinned in Task 3 (`current_none_still_sets_desired`) and Task 11 (`hidden_current_default_is_shown_unranked`).
2. **A state file from a newer cue** (`schema_version: 2`). Expected: an error, never a silent downgrade that drops keys. Pinned in Task 2 (`newer_schema_is_rejected`).
3. **A stale reorder from the panel** (a device connected or was forgotten between render and drop). Expected: the command is refused and the stored order is untouched (spec bug #25). Pinned in Task 10 (`reorder_with_stale_list_is_refused`).
4. **Ordinary topology churn tripping the loop guard** (a dock brings three devices at once; reconcile runs several times). Expected: writes happen only when `desired != current`, so one write per role and no trip. Pinned in Task 8 (`dock_connect_writes_once_and_does_not_trip`).
5. **A virtual device that is the macOS default at first launch** (BlackHole selected as output). Expected: seeding ranks it first and does not flag it "never use", so the first reconcile does nothing. Pinned in Task 9 (`virtual_current_default_is_not_flagged_at_seed`).

## Ported scenarios (audit §5)

Kept, adapted to the strict policy: startup picks top per role; top device connects / leaves; auto off never writes; echo of our own write is a no-op; AirPods taking the mic (and output) on connect are reverted; an outside change is reverted; a fast fight trips the guard; full-duplex device keeps both roles; never-use is per role; virtual devices start never-use and opting back in sticks; new devices keep discovery order; USB port move keeps rank; identical devices seen together stay separate; serial USB and unrelated displays keep their identity; a live device with a location-shaped serial keeps its settings; a late USB descriptor does not strand settings; an unverified offline record cannot donate; simultaneous copies latch; zero UUID keeps exact UIDs; forget removes the key everywhere; old files missing optional fields still decode.

Dropped, and why:

- All kept-pick scenarios (`aPickInControlCenterStays…`, `aPickInThePanelStays…`, `onlyADeviceTheListWouldUseEnds…`, `reorderingTheActiveMicrophoneListClearsAKeptPick`, `…IsHeldInManualMode`, `aSlowAirPodsHandover…`, `aControlCenterWindowWhileAirPodsConnect…`): ADR 0003 removes picks. Click-to-promote replaces them (Task 10).
- Manual-mode AirPods scenarios: with auto off, strict cue does nothing.
- Echo/ordering timing scenarios (`deviceCallbackBeforeDefaultCallback…`, `outputMovingBeforeTheDisconnectArrives…`): strict reconcile is stateless per snapshot; one echo test covers them.
- Pairing, follow-output, speaker/headphone categories, mute, profiles, display hide-once, legacy migrations, forgotten-Bluetooth relisting, Shortcuts redirect, dongle-check deferral: not in the v1 keep set.
- `forgettingOneRolePreservesTheOther`: v1 forget is device-wide (spec §5.8 "every UID-bearing structure").
- `failedSelectionDoesNotClaimDeviceIsCurrent`, listener lifecycle: engine (M3).

### Task 3: `Reason` and `decide()`

**Files:**
- Create: `src/reason.rs`, `src/desired.rs`, `tests/desired.rs`

**Interfaces:**
- Consumes: `State::list`, `Snapshot::device`, `DeviceSnapshot::{alive, streams}`.
- Produces:
  - `pub enum Skip { Disconnected, NotAlive, NoStreams, NeverUse }`, serde snake_case, `Display` prints `disconnected`, `not alive`, `no streams`, `never use`.
  - `pub struct Skipped { pub key: DeviceKey, pub why: Skip }`.
  - `pub struct Reason { pub role: Role, pub desired: Option<DeviceKey>, pub current: Option<DeviceKey>, pub skipped: Vec<Skipped> }`, `Clone, PartialEq, Debug, Serialize`. `Display` gives one log line: `output: desired=spk current=hdmi skipped=[airpods: disconnected, bh: never use]`, with `none` for a missing key.
  - `pub fn decide(state: &State, snap: &Snapshot, role: Role) -> Reason`.

Rule (spec §5.2): walk `order(role)`; the first key that is connected, alive, has streams in `role` and is not never-use is `desired`. Every key before it is in `skipped`, with the first failing check in this order: Disconnected, NotAlive, NoStreams, NeverUse. Keys after `desired` are not listed. With no desired, every key is skipped. `current` comes from `snap.current`. `hidden` is not a skip cause (spec lists four).

### Task 6: The UID registry

**Files:**
- Create: `src/identity/registry.rs` (inline tests)

**Interfaces:**
- Consumes: `State`, `DeviceKey`.
- Produces (crate-public, used by Tasks 8 and 10):
  - `pub(crate) fn rename(state: &mut State, from: &DeviceKey, to: &DeviceKey)`: rewrites `from` to `to` in every UID-bearing structure. In each `order`, duplicates are removed keeping the first occurrence, so `to` lands at the better of the two ranks. In `never_use`, a flag on either key survives (union). In `devices`, `to`'s record is kept if present; otherwise `from`'s record moves to `to`. `paused_reason.key` is rewritten.
  - `pub(crate) fn remove(state: &mut State, key: &DeviceKey)`: drops `key` from the same structures; `paused_reason` is cleared if it names `key`.

That function is the registry: the only place that lists `output.order`, `output.never_use`, `input.order`, `input.never_use`, `devices`, `paused_reason`. Its doc comment says a new UID-bearing field must be added here.
  - `ambiguous_families` holds family strings, not UIDs, so it is out of scope.

### Task 8: Alias merge and the ambiguity latch

**Files:**
- Create: `src/identity/alias.rs`, `tests/alias.rs`

**Interfaces:**
- Consumes: `alias_identity`, `parse_port`, `registry::rename`.
- Produces: `pub struct Merge { pub from: DeviceKey, pub to: DeviceKey }` and `#[doc(hidden)] pub fn merge_aliases(state: &mut State, snap: &Snapshot) -> Vec<Merge>`.

Algorithm (audit §3.3 `reconcilePortChanges`, adapted to one record per key):

1. Candidates: snapshot devices with `alias_identity(d) == Some(id)`.
2. Group candidates by `family`. A family with more than one distinct `port` among them goes into `state.ambiguous_families` (persistent latch).
3. For each candidate whose family is not latched: donors are keys in `state.devices` where the key is not connected, `record.family == Some(id.family)`, and `parse_port(key).endpoint == id.endpoint`. Sort donors by `last_seen` descending, then call `rename(state, donor, candidate)` for each and push a `Merge`.

Run before `remember`, so a donor's record and rank move to the new UID before the new UID could be appended as new.

### Task 9: `reconcile()`, `Action`, `Runtime`, and first-launch seeding

**Files:**
- Create: `src/reconcile.rs`, `src/seed.rs`, `tests/reconcile.rs`, `tests/seed.rs`

**Interfaces:**
- Consumes: `merge_aliases`, `remember`, `decide`, `LoopGuard`.
- Produces:
  - `pub enum Action { SetDefault { role: Role, key: DeviceKey }, PauseAuto { role: Role, key: DeviceKey }, AliasMerged { from: DeviceKey, to: DeviceKey }, Persist }`, `Clone, PartialEq, Debug`.
    - `SetDefault`: the engine sets the role's default; for `Output` it also sets the system output (spec §5.2).
    - `PauseAuto`: the guard tripped. `State.auto_switch` is already `false` and `paused_reason` set; the engine updates the icon and notifies with `paused_reason.message()`. `key` is the device that kept taking the role.
    - `AliasMerged`: info log only.
    - `Persist`: `State` changed; the engine schedules the debounced save.
  - `#[derive(Default)] pub struct Runtime { pub guard: LoopGuard, connected: Option<BTreeSet<DeviceKey>> }`. In memory only.
  - `pub struct Outcome { pub actions: Vec<Action>, pub reasons: Vec<Reason> }`.
  - `pub fn reconcile(state: &mut State, rt: &mut Runtime, snap: &Snapshot, now: Timestamp) -> Outcome`.
  - `pub fn seed(snap: &Snapshot, now: Timestamp) -> State`.

`reconcile` order: clone `state` as `before`; `merge_aliases` (push `AliasMerged`s); `remember(state, snap, rt.connected.as_ref(), now)`; set `rt.connected` to the snapshot keys; for each role in `Role::ALL`: `decide`, push the `Reason`; if `state.auto_switch`, `desired` is `Some` and differs from `current`, call `rt.guard.record(role, now)`. If it trips: set `auto_switch = false`, set `paused_reason` (name from the snapshot device, else the record, else the key), push `PauseAuto`, and **do not** push the write. Otherwise push `SetDefault`. Finally push `Persist` if `*state != before`. Reasons are always two (output, input), auto-switch on or off.

Decision: the 3rd corrective write is replaced by the pause, not issued. The device that keeps taking the role keeps it, which ends the fight.

`seed`: `State::default()` (auto-switch on). For each role, if `snap.current` names a listable device with streams in that role, put it first in `order(role)` and do not flag it never-use even if virtual. Then `remember(&mut state, snap, None, now)` appends the rest in enumeration order and flags virtual ones.

### Task 10: Commands

**Files:**
- Create: `src/commands.rs`, `tests/commands.rs`

**Interfaces:**
- Consumes: `State`, `Runtime` (`guard.reset()`), `Snapshot`, `registry::remove`.
- Produces:
  - `pub enum Command { Reorder { role: Role, order: Vec<DeviceKey> }, Promote { role: Role, key: DeviceKey }, SetNeverUse { role: Role, key: DeviceKey, on: bool }, Forget { key: DeviceKey }, SetAutoSwitch(bool), SetDebug(bool) }`.
  - `pub enum CommandError { UnknownDevice(DeviceKey), StillConnected(DeviceKey), StaleOrder(Role) }` with `Display` and `std::error::Error`.
  - `pub fn apply(state: &mut State, rt: &mut Runtime, snap: &Snapshot, cmd: Command) -> Result<(), CommandError>`. On `Err`, `state` is unchanged. The engine runs `reconcile` after every `Ok` (spec §5.3 "prefs changed").

Semantics:
- `Reorder`: `order` must be a permutation of the stored `order(role)` (same keys, same length, no duplicates), else `StaleOrder`. Move Up/Down are panel-side reorders.
- `Promote`: key must be in `order(role)`, else `UnknownDevice`; moves it to index 0.
- `SetNeverUse`: key must be in `order(role)`; inserts or removes it from `never_use(role)`.
- `Forget`: key must be in `state.devices` or an order, else `UnknownDevice`; must not be in `snap`, else `StillConnected`. Calls `registry::remove` (device-wide, both roles).
- `SetAutoSwitch(true)`: `auto_switch = true`, `paused_reason = None`, `rt.guard.reset()`. `SetAutoSwitch(false)`: `auto_switch = false`; `paused_reason` untouched.
- `SetDebug(b)`: `debug = b`.
